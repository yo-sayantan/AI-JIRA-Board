Setup & Deployment Guide

Everything you need to install the tools, clone the repo, add your Jira token, and get the board running — on Windows, macOS or Linux. Every command is copy-ready.

Reopen this page anytime — it needs nothing running: ./open-guide.sh (macOS/Linux) · double-click open-guide.bat (Windows) · or click the ? button in the board's header when it's up.

What this is

A personal, self-hosted mirror of your Jira board. A background fetcher pulls the tickets assigned to you into a plain data file; a single-file React app renders them — no Jira login, no waiting on the web UI. Two moving parts:

  • The fetch (jira-intern/) — pulls your tickets. Needs one Jira token.
  • The app (dist/index.html) — renders whatever the fetch produced. Needs nothing.
Your tokens never enter the repo. They live in one file outside it (~/.cursor/mcp-secrets.env); everything else points at it by path.

Installing the tools

🪟 Windows

Windows 10 / 11

Easiest path: winget, which ships with Windows 11 and modern Windows 10. Run in PowerShell.

winget install -e --id Git.Git
winget install -e --id Docker.DockerDesktop
winget install -e --id OpenJS.NodeJS.LTS      # optional
winget install -e --id Python.Python.3.12     # optional

Then reboot (Docker Desktop needs it), launch Docker Desktop once, and wait for "Engine running". Docker Desktop will enable WSL 2 for you if it isn't already.

No winget? Install each from its download page in the table above. Use PowerShell (not CMD) for the commands on this page — or Git Bash if you prefer bash syntax.
Path note: commands here use ~/ for your home folder. In PowerShell that's $HOME — e.g. $HOME\.cursor\mcp-secrets.env.
🍎 macOS

macOS 12+

Easiest path: Homebrew. Install it first if you don't have it:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install git
brew install --cask docker      # Docker Desktop
brew install node               # optional
brew install python@3.12        # optional

Open Docker Desktop once from Applications and wait until the whale icon says "Docker Desktop is running". Git may also come from Xcode Command Line Tools: xcode-select --install.

🐧 Linux

Linux (Debian / Ubuntu shown)

sudo apt update
sudo apt install -y git curl python3      # python optional

Docker Engine + Compose plugin, via Docker's official convenience script:

curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"      # run docker without sudo
newgrp docker                        # apply the group now (or log out/in)

Node.js (optional) via nvm:

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
nvm install 20

Fedora/RHEL: swap apt for dnf. Arch: sudo pacman -S git docker docker-compose nodejs.

Verify everything is installed

git --version
docker --version
docker compose version
node --version     # optional
python3 --version  # optional (Windows: python --version)

Each should print a version. If docker errors with "cannot connect to the daemon", Docker Desktop isn't running yet.

Getting the code — Git commands

Clone the repository

git clone https://github.com/yo-sayantan/AI-JIRA-Board.git
cd AI-JIRA-Board

First time using Git on this machine? Set your identity:

git config --global user.name  "Your Name"
git config --global user.email "you@example.com"

Everyday Git

git pull                       # get the latest changes
git status                     # what have I changed?
git switch -c my-change        # start a branch
git add -A                     # stage everything
git commit -m "What I changed" # commit
git push -u origin my-change   # push the branch
Never commit secrets. .gitignore already blocks *.env and the fetched ticket data. Before pushing, a quick sanity check: git status should show no .env files and no jira-intern/data.*.

Configure — two files, once

1

Create your secrets file

macOS / Linux:

mkdir -p ~/.cursor
cp setup/mcp-secrets.env.template ~/.cursor/mcp-secrets.env
chmod 600 ~/.cursor/mcp-secrets.env

Windows (PowerShell):

New-Item -ItemType Directory -Force "$HOME\.cursor" | Out-Null
Copy-Item "setup\mcp-secrets.env.template" "$HOME\.cursor\mcp-secrets.env"

Now open that file and set at least these two lines:

JIRA_URL=https://jira.your-company.example
JIRA_PERSONAL_TOKEN=your-token-here
2

Create your personal config

Your identity and company URLs live outside the repo, at ~/.ai/config.json, so they never enter git.

macOS / Linux:

mkdir -p ~/.ai
cp setup/config.example.json ~/.ai/config.json
chmod 600 ~/.ai/config.json

Windows (PowerShell):

New-Item -ItemType Directory -Force "$HOME\.ai" | Out-Null
Copy-Item "setup\config.example.json" "$HOME\.ai\config.json"

Edit it — your name exactly as Jira shows it (that's how "assigned to me" matches), your company URLs, and the footer branding. Every key is documented in jira-intern/CONFIG.md. No tokens go in this file.

Which config wins: $AI_CONFIG_FILE → ~/.ai/config.json → the tracked jira-intern/config.json template. Check with node jira-intern/local-runner/config.mjs path.
Create this file before your first docker compose up — Docker mounts it, and if the path is missing it silently creates a directory there instead.

Docker — build & deploy

The one command

docker compose up -d --build

Then open http://localhost:4321/dist/index.html ✓

This builds the image (stage 1 compiles the app, stage 2 runs the server + Python fetch), starts a container named jira-board, mounts your secrets read-only, fetches once on boot, and re-fetches every 15 minutes.

Build and run separately

# build the image only
docker compose build --pull
# or with plain docker
docker build -t jira-board:latest .

# run it (plain docker, without compose)
docker run -d --name jira-board -p 4321:4321 \
  -v "$HOME/.cursor/mcp-secrets.env:/root/.cursor/mcp-secrets.env:ro" \
  -v "$(pwd)/jira-intern:/app/jira-intern" \
  jira-board:latest

Windows PowerShell equivalent for the volume flags: -v "${HOME}\.cursor\mcp-secrets.env:/root/.cursor/mcp-secrets.env:ro" and -v "${PWD}\jira-intern:/app/jira-intern".

Managing the container

docker compose logs -f          # watch fetch + server logs
docker compose ps               # is it running?
docker compose restart          # restart without rebuilding
docker compose down             # stop and remove
docker compose up -d --build    # rebuild + redeploy after a code change
docker exec -it jira-board sh   # shell inside the container
docker stats jira-board         # resource usage
docker image prune -f           # clean old layers
Changed anything in src/? You must rebuild (--build) — the app is baked into the image. Changing only data needs no rebuild; the container refetches on its own.

One-click launcher (macOS / Linux)

Starts Docker if needed, frees the port, rebuilds, redeploys, waits for health, and opens the board. Safe to run repeatedly — it never stacks containers or drifts ports.

./start-jira-board.sh

For a Desktop shortcut, copy setup/Start Jira Board.command.template to your Desktop, set REPO_DIR inside it, then chmod +x it and double-click.

AI — the AI Intern container, local models and cloud APIs

How it works

The board container runs no AI. When a PR Readiness Report is generated it writes the deterministic base and hands the ticket to a second container from the same image, JIRA-AI-Intern, which enriches the report the way Settings → AI usage says. Nothing runs on your Mac outside Docker, and there is no terminal step: Regenerate and the bulk runs follow the mode you chose. Off keeps reports deterministic.

ModeWhat runsSpeed / costNeeds
Local modelOllama in the JIRA-LLM container, CPU-onlySlow — a few tokens per second on an 8B model — free, nothing leaves your machinea .gguf file in jira-intern/models/
Cloud APIClaude (Messages API) or any OpenAI-compatible endpointFast; uses tokens on your keyANTHROPIC_API_KEY or OPENAI_API_KEY in the secrets file
Why slow? Docker Desktop on macOS gives containers no GPU, so a local model runs on the CPU cores you gave the Docker VM. A natively installed Ollama uses the Apple GPU and is 5–6× faster; point the AI Intern at it with AI_LOCAL_ENDPOINT=http://host.docker.internal:11434 bash start-jira-board.sh and skip the JIRA-LLM container entirely.

Which model fits your Mac — memory is the only question

A model needs its weights plus a working context in memory. Inside Docker the ceiling is the Docker VM's memory, not the Mac's: Docker Desktop → Settings → Resources → Memory (8 GB by default on many installs; give it 12–16 GB for the 8–9B class). Settings → AI usage shows the VM's memory and marks each model fits, tight or too big. Download the single-file Q4_K_M build (the sweet spot of size and quality).

Where to download, where to place

  1. Open the model's GGUF page on Hugging Face — search the model name plus GGUF; prefer the official repository, then unsloth or bartowski.
  2. In Files, download the single file ending in Q4_K_M.gguf (not a sharded -00001-of-0000N set).
  3. Move it into jira-intern/models/ in this repository. Keep the file name simple (letters, digits, dots, dashes).
  4. In the board: Settings → AI usage → Local model, then bash start-jira-board.sh once so the JIRA-LLM runtime starts. Within a minute the file shows under Ready in the runtime — click it.
# alternative when the network is fast: let Ollama fetch a model by tag
docker exec JIRA-LLM ollama pull qwen3:8b
# see what the runtime has / is doing
docker exec JIRA-LLM ollama list
docker logs -f JIRA-AI-Intern
Disk: the runtime keeps its own copy of each registered model, so a 5 GB file uses about 10 GB in total. Delete the .gguf from jira-intern/models/ once it shows as ready if space is tight.

Cloud API instead

Add the key to your secrets file (~/.cursor/mcp-secrets.env), redeploy, then pick Cloud API in Settings and a model — claude-opus-5 is the default, claude-sonnet-5 is cheaper and faster. For an OpenAI-compatible endpoint set OPENAI_BASE_URL as well.

ANTHROPIC_API_KEY=sk-ant-…          # Claude
OPENAI_API_KEY=…                    # OpenAI-compatible
OPENAI_BASE_URL=https://api.openai.com/v1

A report costs roughly one large prompt (ticket + base report + diffs) and a few thousand output tokens. Effort in Settings scales how long the model may think and how much of the diff it is shown.

Other ways to run

📄 Static file — no server

The build is one self-contained HTML file. If a data dump exists, just open it:

# macOS
open dist/index.html
# Linux
xdg-open dist/index.html
# Windows
start dist\index.html

Press r to re-read the latest data.

🖥️ Live local server

The header button becomes a real Refresh that runs the fetch on your machine.

npm install
npm run serve

Serves on port 4321. Needs Node.js 20+.

Build & develop the app

npm install        # install dependencies
npm run dev        # localhost:5173 — sample data, hot reload
npm run typecheck  # tsc --noEmit
npm run build      # → dist/index.html (single file)

Refresh the ticket data by hand

bash jira-intern/local-runner/run-intern.sh        # active tickets (daily)
bash jira-intern/local-runner/update-completed.sh  # full Completed archive (weekly)

Both rewrite jira-intern/data.json and data.js; reload the board to see the result.

Troubleshooting

SymptomFix
Board loads but is emptyNo data yet. Wait for the boot fetch, check docker compose logs -f, or run the fetch by hand.
"no JIRA_PERSONAL_TOKEN found — skipping fetch"Your secrets file isn't mounted or readable. Confirm ~/.cursor/mcp-secrets.env exists and contains the token.
docker: cannot connect to the Docker daemonDocker Desktop isn't running. Launch it and wait for "Engine running".
Port 4321 already in usedocker compose down, or run on another port: PORT=8080 docker compose up -d --build.
Name or service not known for your Jira hostDocker DNS, common on VPN. Uncomment the dns: block in docker-compose.yml and recreate.
Container exits immediatelydocker logs JIRA-Board — usually a bad token or an unreachable host.
Changed src/ but the UI looks oldRebuild: docker compose up -d --build.
Permission denied running docker on Linuxsudo usermod -aG docker "$USER", then log out and back in.
./start-jira-board.sh: Permission deniedchmod +x start-jira-board.sh
